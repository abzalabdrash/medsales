# medsales — база и парсеры для MedRoute KZ

Данные и пайплайн для сервиса сравнения цен на **медуслуги и лекарства** в
Казахстане. Этот репозиторий — слой данных: парсеры, нормализация, QA,
геообогащение и готовая единая база. **AI-агент делается отдельно**, здесь
для него подготовлены схема, инструменты и промпты.

## Что внутри

| | |
|---|---|
| **10 047** препаратов | эталон из приказов МЗ РК: ТН, МНН, форма, дозировка, **размер упаковки**, предельные цены |
| **538** позиций | перечень бесплатного амбулаторного обеспечения (ҚР ДСМ-75) с МКБ-10 и ATC |
| **1 189 / 1 495** | предельные цены по МНН / медизделия для ГОБМП и ОСМС |
| **5 121** | препаратов с ATC-кодом — основа подбора аналогов |
| **31 707** цен | медуслуги: 226 брендов, 308 филиалов, 13 городов, 4 775 услуг |
| **1 260** отзывов | о клиниках |

Единая база: `data/medsales.db` (SQLite, ~26 МБ).

## Быстрый старт

```bash
pip install -r requirements.txt
```

Пересобрать базу с нуля:

```bash
python -m pharma.ingest_ref && python -m pharma.ingest_benefits && python -m pharma.merge
```

## Ключевые модули

| Модуль | Что делает |
|---|---|
| `pharma/forms.py` | разбор лекформы → доза, объём, **размер упаковки** (99% покрытия) |
| `pharma/course.py` | **расчёт потребности на курс** — сколько упаковок реально нужно |
| `pharma/qa.py` | валидатор цен: ловит битый парсинг и переплату над предельной ценой |
| `pharma/merge.py` | склейка препаратов и услуг в одну базу + представления `v_place`, `v_item` |
| `pharma/geo/twogis.py` | 2GIS: поиск, рейтинги, **deeplink'и** в приложение |
| `pharma/agent/prompts.py` | промпты агента |
| `pharma/agent/cards.py` | контракт карточек выдачи |

## Как получить ключи 2GIS

Deeplink'и (`dgis://...`) работают **без ключа и без квоты** — ключ нужен
только для поиска организаций, рейтингов и отзывов.

1. Зайти на <https://platform.2gis.ru/> → зарегистрироваться.
2. Platform Manager → **Создать демо-ключ**.
3. Выбрать сервис **Places API (Каталог)**.
4. Скопировать ключ.

Лимиты демо-ключа: **1 000 запросов на сервис, 1 месяц**, максимум 5 страниц
по 10 объектов в ответе. Контакты организаций в демо не отдаются.

Двух ключей достаточно: 2 000 запросов против 308 филиалов + аптеки.

```bash
export TWOGIS_KEYS="ключ1,ключ2"          # bash
$env:TWOGIS_KEYS="ключ1,ключ2"            # PowerShell

python -m pharma.geo.enrich --dry-run                 # сколько работы, без трат
python -m pharma.geo.enrich --city Алматы --limit 150
python -m pharma.geo.enrich --city Алматы --pharmacies
```

Ответы кэшируются на диск (`data/cache/2gis/`) — повторный запуск квоту не
тратит. Ключи ротируются автоматически, при исчерпании скрипт остановится с
понятной ошибкой, а не молча испортит данные.

## Для разработчика агента

Работать через представления, а не через сырые таблицы:

```sql
-- любая точка на карте: и клиника, и аптека
SELECT kind, place_name, city, address, lat, lng, rating, twogis_search_url
FROM v_place WHERE city = 'Алматы';

-- любая позиция чека: и услуга, и препарат
SELECT kind, title, inn, atc, price, org_name, pack_size, price_cap_retail
FROM v_item WHERE price IS NOT NULL;
```

Три вещи, ради которых всё это собиралось:

1. **`drug_ref.pack_size`** — позволяет посчитать курс. «Ае-вит 1 капс. 3 р/д
   40 дней» это 120 капсул, то есть 4 упаковки, а не одна. См. `course.py`.
2. **`drug_ref.price_cap_retail`** — предельная розничная цена МЗ РК. Даёт
   право сказать «в этой аптеке переплата 33%».
3. **`free_drug`** — если препарат тут есть и диагноз подходит, покупать его
   не нужно вообще.

Промпты и контракт карточек — в `pharma/agent/`. Основной принцип: модель
читает почерк и объясняет результат, а считает, ищет и оптимизирует код.
Цены и адреса модель только копирует из ответа инструмента.

## Ограничения

- Данные носят справочный характер и не заменяют консультацию врача.
- Предложения аптек собраны по сети «Еврофарма»; другие сети — следующий шаг.
- Аптеки с производственным отделом (экстемпоральные препараты) в базе
  помечаются флагом `pharmacy.has_compounding`, данные пока не собраны.
- Часть цен на услуги не проходит QA (см. `pharma/qa.py`) — используйте
  фильтр по `qa_flag`.
